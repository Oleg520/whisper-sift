# Whisper Sift Backlog

Текущий backlog проекта с приоритетами и чекбоксами для отслеживания прогресса.

Стратегическое направление проекта вынесено в [ROADMAP.md](./ROADMAP.md).

Статусы:

- `[ ]` — не начато
- `[-]` — в работе
- `[x]` — завершено

Последнее обновление: 2026-04-08

## P0 — Критично для надежности

- [x] Починить реальный bootstrap зависимостей
  Автоустановка теперь вызывается до импорта модуля транскрибации, поэтому bootstrap работает корректно в чистом окружении.

- [x] Добавить валидацию `pipeline` для `--formats`
  Для `pipeline` формат `txt` теперь автоматически добавляется, если пользователь его не указал, и CLI явно сообщает об этом.

- [x] Убрать Windows-специфичность подготовки `ffmpeg`
  Подготовка `ffmpeg` стала платформо-независимой: сначала используется системный бинарник, затем fallback на `imageio-ffmpeg` с корректным алиасом на Windows, Linux и macOS.

- [x] Нормализовать обработку ошибок CLI
  CLI теперь возвращает стабильные коды выхода и понятные сообщения для `FileNotFoundError`, сбоев bootstrap и других типовых runtime-ошибок.

## P1 — Качество результата и UX

- [x] Добавить unit-тесты на эвристики выделения вопросов
  Добавлены Python-тесты на нормализацию пробелов, сегментацию, фильтрацию шума, дедупликацию и смежные helper-функции CLI/runtime.

- [ ] Улучшить эвристику извлечения вопросов
  Лучше обрабатывать длинные фразы, несколько вопросов в одной реплике, повторяющиеся куски ASR и пограничные случаи без идеальной пунктуации.

- [ ] Добавить `json`-вывод
  Нужен структурированный формат результатов для автоматизации: исходный файл, модель, устройство, список вопросов, метаданные выполнения.

- [x] Добавить команду `doctor` или `bootstrap`
  Появилась команда `doctor`, которая проверяет зависимости, `ffmpeg`, Python-окружение и доступность `cuda/mps`, а также умеет пробовать доустановить missing runtime-зависимости.

## P2 — Дальнейшее развитие

- [ ] Вынести runtime-артефакты из корня репозитория
  Временные файлы и служебные бинарники лучше хранить в cache-директории пользователя, а не в рабочем дереве проекта.

- [ ] Добавить инженерную обвязку
  Подключить `pytest`, `ruff`, CI workflow и базовые автоматические проверки.

- [ ] Поддержать speaker-aware улучшения
  Перейти от чисто текстовых эвристик к diarization или хотя бы более точному разделению реплик интервьюера и кандидата.
