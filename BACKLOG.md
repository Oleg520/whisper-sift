# Whisper Sift Backlog

Текущий backlog проекта с приоритетами и чекбоксами для отслеживания прогресса.

Стратегическое направление проекта вынесено в [ROADMAP.md](./ROADMAP.md).

Статусы:

- `[ ]` — не начато
- `[-]` — в работе
- `[x]` — завершено

Последнее обновление: 2026-04-08

## P0 — Критично для надежности

- [ ] Починить реальный bootstrap зависимостей
  Сейчас автоустановка вызывается слишком поздно относительно импортов, поэтому в чистом окружении приложение может упасть до установки `torch`, `openai-whisper` и `imageio-ffmpeg`.

- [ ] Добавить валидацию `pipeline` для `--formats`
  Если пользователь исключает `txt` из форматов, извлечение вопросов не сработает. Нужно либо принудительно добавлять `txt`, либо явно завершаться с понятной ошибкой.

- [ ] Убрать Windows-специфичность подготовки `ffmpeg`
  Текущая реализация ориентирована на `ffmpeg.exe`. Нужно сделать платформо-независимый вариант для Windows, Linux и macOS.

- [ ] Нормализовать обработку ошибок CLI
  Нужны понятные сообщения и стабильные коды выхода для типовых сбоев: отсутствующий файл, невалидный параметр, отсутствие GPU, проблемы с зависимостями.

## P1 — Качество результата и UX

- [ ] Добавить unit-тесты на эвристики выделения вопросов
  Проверить нормализацию пробелов, сегментацию, фильтрацию шума и дедупликацию.

- [ ] Улучшить эвристику извлечения вопросов
  Лучше обрабатывать длинные фразы, несколько вопросов в одной реплике, повторяющиеся куски ASR и пограничные случаи без идеальной пунктуации.

- [ ] Добавить `json`-вывод
  Нужен структурированный формат результатов для автоматизации: исходный файл, модель, устройство, список вопросов, метаданные выполнения.

- [ ] Добавить команду `doctor` или `bootstrap`
  Отдельная команда должна проверять окружение и объяснять, почему используется CPU, доступны ли `cuda/mps`, найден ли `ffmpeg` и хватает ли зависимостей.

## P2 — Дальнейшее развитие

- [ ] Вынести runtime-артефакты из корня репозитория
  Временные файлы и служебные бинарники лучше хранить в cache-директории пользователя, а не в рабочем дереве проекта.

- [ ] Добавить инженерную обвязку
  Подключить `pytest`, `ruff`, CI workflow и базовые автоматические проверки.

- [ ] Поддержать speaker-aware улучшения
  Перейти от чисто текстовых эвристик к diarization или хотя бы более точному разделению реплик интервьюера и кандидата.
