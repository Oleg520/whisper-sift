# Whisper Sift Roadmap

Стратегический план развития проекта.

Этот файл отвечает на вопрос:

- куда развивается проект
- какие цели важнее всего
- в каком порядке логично усиливать продукт

Для конкретных задач и отслеживания прогресса используй [BACKLOG.md](./BACKLOG.md).

Последнее обновление: 2026-04-08

## Текущее состояние

Whisper Sift уже является рабочим MVP:

- умеет расшифровывать медиафайлы через Whisper
- умеет извлекать вопросы из готовых расшифровок
- поддерживает CLI-пайплайн
- оформлен как Python-пакет
- уже имеет базовую поддержку выбора `cpu/cuda/mps`

При этом продукт пока находится на стадии удобного инженерного инструмента, а не зрелого production-ready решения.

## Ключевые цели

### 1. Надежность запуска

Пользователь должен получать предсказуемое поведение в чистом окружении:

- зависимости должны ставиться или проверяться корректно
- ошибки должны быть понятными
- поведение на разных ОС должно быть стабильным

### 2. Качество результатов

Извлечение вопросов должно быть заметно более устойчивым к шумной расшифровке:

- меньше ложных срабатываний
- меньше дублей
- лучше разбиение длинных реплик
- более точное отделение вопросов интервьюера от остального текста

### 3. Удобство использования

Инструмент должен быть удобен для повторяемой повседневной работы:

- понятные команды CLI
- диагностический режим
- структурированный экспорт
- предсказуемые пути сохранения

### 4. Инженерная зрелость

Проект должен стать удобным для долгой поддержки:

- тесты
- линтеры
- CI
- прозрачный процесс релизов

## Приоритетный порядок развития

### Этап 1. Стабилизация ядра

Сначала усиливаем надежность:

- bootstrap зависимостей
- платформо-независимый `ffmpeg`
- валидация CLI-параметров
- понятная обработка ошибок

Это самый важный этап, потому что без него любые дальнейшие улучшения будут стоять на неустойчивой основе.

### Этап 2. Качество извлечения вопросов

После стабилизации запуска улучшаем самую ценную логику продукта:

- тесты на эвристики
- доработка фильтрации шума
- лучшее разбиение и дедупликация вопросов
- подготовка к speaker-aware логике

### Этап 3. Улучшение UX

Когда базовый пайплайн станет надежным и предсказуемым, можно усиливать пользовательский опыт:

- `doctor` / `bootstrap` команда
- `json`-экспорт
- конфиг-файл для повторяемых запусков
- более информативные summary после выполнения

### Этап 4. Подготовка к росту

Если проект станет использоваться регулярно или публично развиваться, стоит вложиться в:

- CI
- release workflow
- тестовую инфраструктуру
- более аккуратное управление runtime-артефактами

## Ближайший фокус

На ближайший цикл разработки логично взять 4 направления:

1. Исправить bootstrap зависимостей.
2. Исправить edge case в `pipeline`, если нет `txt`.
3. Добавить первые тесты на эвристику выделения вопросов.
4. Добавить команду `doctor` для диагностики окружения.

## Дальняя перспектива

Если проект продолжит расти, самые сильные улучшения будут здесь:

- speaker diarization
- более точное разделение ролей в интервью
- экспорт в richer-форматы
- интеграции с автоматизированными workflow
